## 1. 计算逻辑说明

与平台 `lib/productization/sales/roi.ts` 口径一致，输入四项参数：

| 输入项 | 符号 | 说明 | 默认值（示例） |
|--------|------|------|----------------|
| 员工人数 | `E` | 覆盖健身区的员工规模 | 100 |
| 空间面积 | `S` | 健身区面积（㎡） | 500 |
| 项目预算 | `B` | 建设/改造总预算（元） | 250,000 |
| 预期利用率 | `U` | 建成后预期使用率（%） | 75 |

输出三项：

| 输出项 | 含义 |
|--------|------|
| **生产力影响** | 因健康设施带来的效率提升估算（%） |
| **健康项目影响** | 福利/留存/满意度相关估算（%） |
| **估算 ROI** | 年化收益 / 项目预算（%） |

## 2. 使用步骤（销售现场）

### Step 1 — 收集参数（3 分钟）

向客户确认：

1. 「贵司覆盖该健身区的员工大约多少人？」→ `E`  
2. 「健身区大概多少平米？」→ `S`  
3. 「这轮改造预算大概在什么区间？」→ `B`  
4. 「建成后您预期利用率大概多少？」→ `U`（通常 60–85%）

### Step 2 — 计算（可用 API 或下表手算）

**API（内部）：** `GET /api/productization/sales` 返回 ROI 字段。

**手算参考（与默认示例对齐）：**

| 输入 | E=100, S=500, B=250,000, U=75% |
|------|--------------------------------|
| 生产力影响 | 约 **32%**（量级） |
| 健康项目影响 | 约 **28%**（量级） |
| 估算 ROI | 约 **150%+**（量级，随 B 变化敏感） |

> ⚠️ 当 `B` 很小或 `E` 很大时 ROI % 会偏高，讲解时强调 **「方向性价值」** 而非承诺财务回报。

### Step 3 — 叙事模板（2 分钟）

> 「以贵司 **100 人、500㎡、25 万预算** 为例，健身区若达到 **75%** 利用率，员工健康与效率的复合收益，估算可覆盖项目投资的一个可观比例——**我们的工具价值在于把方案与预算周期从 3 周压到 3 天，让您更快进入施工与运营阶段，提前享受这部分收益。**」

## 5. 注意事项（必读）

| 原则 | 说明 |
|------|------|
| 不作收益承诺 | ROI 为模型估算，不写进合同对赌 |
| 分项讲解 | 生产力 vs 健康福利，对应不同决策者关注点 |
| HR 看留存 | 强调福利竞争力、招聘雇主品牌 |
| 行政看周期 | 强调 **时间节省** 与 **PDF 即用** |
| 财务看预算 | 强调 **预算结构化** 与 **招采合规文件** |
